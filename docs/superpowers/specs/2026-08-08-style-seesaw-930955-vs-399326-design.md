# 风格跷跷板 930955 vs 399326 研究包设计

## 目标

围绕 `红利低波100 (930955)` 与 `深证成长40 (399326)` 建立一个**长期可复用**的风格跷跷板研究包，第一版只产出一个 `analysis-first` JSON，用来回答：

- 当前市场更偏红利还是更偏成长
- 这种偏向是否已经走到历史较极端的位置
- 红利和成长各自当前事件处在什么阶段
- 当前事件的估值、股息率、股债收益差是否发生了关键变化
- 历史上类似事件通常如何修复

本设计服务研究，不直接生成买卖信号，不输出因果解释，不直接渲染图形页面。

## 研究初心

这个研究包必须始终服务于以下初心：

- 重点不是优化日报界面
- 重点不是生成投资口号
- 重点不是给出“该不该买”的结论
- 重点是把沉淀下来的数据组织成**可重复观察、可长期复用**的风格对比框架

换句话说，第一版的成功标准不是“图做得好不好看”，而是：

> 下次再出现价值/红利被抛弃、成长被杀估值时，只看这一个 JSON，就能快速知道当前处在哪个历史位置。

## 范围

### 本次只做

- 单一对比组：`930955` vs `399326`
- 单一产物：`analysis-first` JSON
- 基于本地已有归档数据计算
- 基于截至 `2026-08-07` 的有效交易日数据输出
- 使用现有事件库与事件切分规则

### 本次不做

- 不做图
- 不做页面
- 不做 ECharts 配置
- 不做多组对比统一框架
- 不做港股补充
- 不做行业风格扩展
- 不做买点打分
- 不做因果归因
- 不做长段解释模板

## 为什么选这组

先只做 `930955 vs 399326`，原因不是它最全面，而是它最鲜明：

- `930955` 更接近高股息、低波动、防御、利率敏感型风格
- `399326` 更接近高估值成长、科技、风险偏好敏感型风格

它们是当前研究里最容易形成反差的一组样本。先做透这一组，才有资格以后复制到：

- `沪深300 vs 国证2000`
- `价值 vs 成长` 的更纯因子组合

## 数据输入

第一版只依赖当前仓库里已经稳定存在的数据：

- `data/archive/index_eod/930955.json`
- `data/archive/index_eod/399326.json`
- `data/archive/index_valuation_percentile/930955.json`
- `data/archive/index_valuation_percentile/399326.json`
- `data/archive/index_dividend_ratio/930955.json`
- `data/archive/index_dividend_ratio/399326.json`
- `data/archive/bond_10y/china_10y.json`
- 已有事件库与相似事件匹配逻辑

### 样本期

- 价格和相对比值：使用两指数可对齐的全部有效样本
- 估值/股息率/股债收益差联合分析：统一从 `2017-12-08` 开始
- 当前有效截止日固定为 `2026-08-07`

## 输出文件

第一版只输出一个文件：

- `data/research/style_seesaw_930955_vs_399326.json`

该文件面向未来前端直接消费，因此以**算好的分析结果**为主，而不是原始大时序。

## 输出结构

顶层固定为五块：

```json
{
  "meta": {},
  "current": {},
  "distribution": {},
  "similar_events": {},
  "trace": {}
}
```

### `meta`

记录研究上下文与规则版本：

- `pair_id`
- `as_of_date`
- `generated_at`
- `sample_start`
- `left.index_code`
- `left.index_name`
- `right.index_code`
- `right.index_name`
- `event_rule_version`

### `current`

记录当前这组风格跷跷板的核心状态：

- 当前相对净值比
- 当前相对净值比分位
- `60日` z-score
- `120日` z-score
- 左侧当前事件卡
- 右侧当前事件卡
- 当前风格状态标签

#### 事件卡字段

`left_event` / `right_event` 至少包含：

- `event_id`
- `peak_date`
- `trough_date`
- `recovery_date`
- `recovered`
- `recovery_rule`
- `max_drawdown`
- `drawdown_days`
- `drawdown_percentile`
- `peak_pe`
- `trough_pe`
- `latest_pe`
- `pe_change_peak_to_trough`
- `pe_change_peak_to_latest`
- `peak_dividend_yield`
- `trough_dividend_yield`
- `latest_dividend_yield`
- `peak_bond_10y`
- `trough_bond_10y`
- `latest_bond_10y`
- `earnings_yield_spread_peak`
- `earnings_yield_spread_trough`
- `earnings_yield_spread_latest`

#### `style_state`

只允许给出**事实型标签**，例如：

- `dividend_stronger`
- `growth_stronger`
- `balanced`

并附有限的 `evidence` 列表，例如：

- `relative_ratio_high`
- `growth_drawdown_deeper`
- `dividend_spread_improved`

它是状态摘要，不是投资建议。

### `distribution`

记录当前状态在历史中的位置，以及历史同类事件如何修复。

至少包含：

- `relative_ratio_percentile`
- `left_drawdown_percentile`
- `right_drawdown_percentile`
- `left_repair_distribution`
- `right_repair_distribution`
- `relative_repair_distribution`

#### 修复分布口径

每个分布统一按以下 horizon 输出：

- `21d`
- `63d`
- `126d`
- `252d`

每个 horizon 只放：

- `sample_size`
- `p25`
- `p50`
- `p75`

第一版不额外堆更多统计量，防止信息过载。

### `similar_events`

记录当前左右两侧事件各自最相似的历史事件。

建议结构：

- `left_event_matches`
- `right_event_matches`

每条 match 只保留前端和研究最需要的字段：

- `event_id`
- `trough_date`
- `max_drawdown`
- `drawdown_days`
- `recovery_rule`
- `peak_pe`
- `trough_pe`
- `peak_dividend_yield`
- `trough_dividend_yield`
- `forward_21d`
- `forward_63d`
- `forward_126d`

第一版不直接输出复杂的“相似度打分解释文本”。

### `trace`

只保留最小必要的可追溯信息，避免结果变成黑箱：

- `left_event_id`
- `right_event_id`
- `left_match_pool_size`
- `right_match_pool_size`
- `relative_ratio_sample_size`
- `left_drawdown_sample_size`
- `right_drawdown_sample_size`
- `raw_metrics`

`raw_metrics` 只放：

- 当前相对比值原值
- 当前分位原值
- 当前 PE、股息率、10Y 国债原值
- 当前盈利收益率股债差原值

不把整段原始时序塞进这个 JSON。

## 第一版要算哪些指标

第一版只算六类指标。

### 1. 相对净值比

定义：

- `relative_ratio = close_930955 / close_399326`

输出：

- 当前值
- 历史分位
- `60日` z-score
- `120日` z-score

作用：

- 它是整个风格跷跷板的主指标
- 用来回答当前市场到底更偏向红利还是成长

### 2. 双边当前事件深度

定义：

- 各自当前事件的最大回撤
- 在各自历史事件样本中的分位
- 当前事件持续时间
- 是否结束、如何结束

作用：

- 用来区分“只是普通回调”还是“已经进入历史较深的一档”

### 3. 估值变化

定义：

- `peak -> trough -> latest` 的 PE 变化

作用：

- 对成长侧，重点回答“是否在杀估值”
- 对红利侧，重点回答“是不是重新便宜了一些”

### 4. 股息率与股债收益差环境

定义：

- 股息率变化
- 10Y 国债收益率变化
- `earnings_yield_spread = 100 / PE - bond_10y`

作用：

- 重点帮助判断红利侧在利率环境下的相对吸引力是否改善

### 5. 历史修复分布

定义：

- 同类事件谷底后 `21/63/126/252` 日收益分布

作用：

- 不做预测
- 只回答“历史上这类事件通常怎么修复”

### 6. 相似事件

定义：

- 基于同指数、同严重级别、上下文优先的历史邻居

作用：

- 帮助快速找到可对照案例
- 但不把相似事件当作未来镜像

## 第一版明确不算哪些东西

为了不偏离研究初心，第一版明确不做：

- 不加大堆宏观变量
- 不加行业暴露
- 不加技术指标拼盘
- 不做原因归因分数
- 不做买点评分
- 不把 `大盘/小盘` 一起混进同一个 JSON

## 生成方式

建议作为独立研究模块实现，不接入当前日报运行链路。

建议命令形态：

- `python -m src.research.style_seesaw_930955_vs_399326`

运行结果：

- 读取本地归档
- 计算分析结果
- 输出到 `data/research/style_seesaw_930955_vs_399326.json`

它不能：

- 联网抓新数据
- 修改 `data/archive`
- 修改日常邮件流程

## 质量要求

第一版最重要的不是“字段多”，而是结果可信。

因此至少要满足：

- 截止日固定为 `2026-08-07`
- 左右两边数据日期对齐清楚
- 所有分位都带样本数
- 当前事件卡字段完整
- 相似事件池大小可追溯
- 缺失值明确输出 `null`
- 不用主观文本替代指标

## 成功标准

第一版成功，不看图，不看页面，只看三个问题能否回答：

1. 当前 `930955 vs 399326` 的风格偏向是否已经走到历史极端区间？
2. 当前红利事件和成长事件分别处在什么深度与阶段？
3. 历史上类似事件的修复分布和最相似案例是什么？

如果这个 JSON 能稳定回答这三个问题，就说明第一版研究包成立。

## 下一步边界

- 用 ECharts 渲染
- 复制到 `沪深300 vs 国证2000`
- 抽象成更通用的风格对比框架

在此之前，不做视觉实现，不扩展更多对比组。
